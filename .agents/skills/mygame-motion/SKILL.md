# MYGAME 动态与动画

先读 [项目约定](../PROJECT.md)，引擎 API 按需读 [phaser-engineer](../phaser-engineer/SKILL.md)。本技能用于用户授权的表现修改，不自动启动正式英雄动画制作。

## 先确定反馈目的

为当前修改写一张小表：事件、玩家需要看懂什么、起始/峰值/结束状态、计时来源、可否中断、视觉优先级、降低动效替代。持续时间先作为可调工作值，不冒充已确认规则。

- UI 动态：悬停/按下/选中、装备拖拽及取消、模式切换、资源条、说明出现与收起。动画表达真实状态，不抢占指针、延迟交易或把取消当确认。
- 战斗动画：起手、释放、飞行、命中/闪避、恢复、死亡。优先分清来源、目标与结算时刻；强度来自节奏与层级，不仅来自更多粒子或震屏。
- 材质/字体/颜色与当前界面一致。色彩之外保留文字、形状或位置识别；重要数字与操作区不能被闪光遮住。

## 接入现有契约

1. 查 [渲染接口](../../../src/renderer/types.ts)、[渲染器](../../../src/renderer/PhaserBattleRenderer.ts)、[反馈聚合](../../../src/renderer/feedback.js) 与 [COMBAT](../../../docs/COMBAT.md)。按真实事件字段做表现，不用伪造伤害数字补画面。
2. 弹道绑定单位唯一 ID 与发射/到达 tick；单位死亡、同槽补怪后旧动画不得命中新实例。动画不得改变已发射快照或再发结算事件。
3. 战斗关联时间从模拟读取。若采用 Phaser Tween/AnimationManager，明确其如何随模拟暂停、销毁和恢复；纯 UI 过渡可用 CSS，但不能驱动战斗状态。
4. 复用现有弹道/浮字/粒子对象池，定义视觉上限与低优先级丢弃顺序。丢表现不丢逻辑，不消耗战斗 RNG。
5. 说明、后台、旋转和手动暂停逐项叠加验证；场景退出移除监听器、tween与对象引用。降低动效保留可读的静态结果，不增加游戏难度。

## 验收

先按一个普通攻击、一个技能与密集战斗观察完整过程，再查死亡/补位、暂停中途、恢复、重复进出与降低动效。

- 复用 [battle-interaction-check](../../../scripts/battle-interaction-check.mjs)、[engine-check](../../../scripts/engine-check.mjs)、[battle-visual-check](../../../scripts/battle-visual-check.mjs)；按影响选运行项。
- 若改变事件消费或时钟，检查同种子、同指令下动效开关不改变生命/资源/奖励/随机轨迹。
- 提供真实截图及必要的短录像或时间点序列，标注普通/高频场景与实际设备。性能按 [mygame-performance](../mygame-performance/SKILL.md) 记录。
- 不只写“更顺滑”；说明玩家可辨认的变化、测试结果和仍需视觉反馈的部分。
