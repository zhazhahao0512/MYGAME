# MYGAME 性能

先读 [项目约定](../PROJECT.md)、[FRAMEWORK](../../../docs/FRAMEWORK.md) 和 [现有引擎检查](../../../scripts/engine-check.mjs)。按需读取 [phaser-engineer](../phaser-engineer/SKILL.md)，先采样再改热点。

## 建立可比较基准

记录提交、浏览器/设备、可见或无头、视口/DPR、WebGL或Canvas、画质、随机种子、暖机和采样时长。参考 60Hz 的整帧预算约 16.7ms，120Hz 约 8.3ms；目标是工作目标，不能代替实际设备测量。

| 场景 | 记录内容 |
| --- | --- |
| 首次进入/再次进入战斗 | 资源下载与缓存、字体/纹理加载、可操作时间 |
| 普通战斗/高攻速与密集特效 | 帧间隔 P50/P95/P99、超预算比例、模拟耗时、主线程长任务、对象及粒子/弹道峰值 |
| 暂停/后台/旋转/切页 | 是否偷跑、恢复追赶、布局抖动、画布重建 |
| 连续战斗/反复进出 | 销毁后的对象/监听器/画布、可用时记录堆内存趋势；自然 GC 回落不算泄漏修复证明 |
| 手机或较弱设备 | 同场景实际设备帧间隔与交互；CPU节流、触屏模拟与真机分别标注 |

现有 engine-check 的 simulationP95Ms 只计 advance 内战斗步进，不含整个渲染帧。actualFps 为引擎汇总指标，不能替代帧分布；requestAnimationFrame 间隔包含调度影响，不等于 GPU 执行时长。GPU 或内存指标不可得时写未测。

## 诊断与修改

1. 用已有 `npm run test:engine` 建立对象池/回退基线；浏览器 trace 或独立临时采样补缺失指标，不为采样向产品界面加调试控件。
2. 区分模拟 CPU、Canvas/WebGL、DOM布局/绘制、纹理/字体上传和分配回收。先定位，再选择减少重复属性刷新、批次/图集、对象复用、按需布局或资源加载。
3. 动态文字先避免无变化的 setText 和 DOM 重写，再按证据评估位图字。保留中文字符覆盖与可读性，不能按通用指南盲换字体或 HUD 技术。
4. 重用现有池并保持有界。质量降级只影响表现，不减少攻击次数、漏事件、修改 RNG 或改变固定模拟步。清理 scene、tween、ResizeObserver 和监听器。
5. 每次只改可解释的热点，在相同条件重测。至少用重复采样确认差异不是噪声；报告前后帧分布与内存/对象趋势，不只挑最高 FPS。

## 结束条件

性能收益可复现，相关交互与模拟行为未回归。视觉变化用 [mygame-motion](../mygame-motion/SKILL.md) 与真实截图/连续播放检查。若瓶颈未定位或无真机条件，说明证据缺口，不能承诺玩家设备帧率。
