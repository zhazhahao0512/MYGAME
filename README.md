# 小队远征

电脑浏览器优先的 2D 单人自动战斗游戏框架。页面、整局流程和统一战斗基础已接入；岚牙、砺山、烬璃、朔影、泠汐五名正式英雄及78件装备已接入，支持独立技能升级与托管。首版数值仍待平衡。所有头像、技能图标和装备图标使用文字方框，不依赖外部图片或字体服务。

## 运行

需要 Node.js 22.12 或更高版本。采用 Phaser 3.90 + Vite；战斗表现层使用 TypeScript，现有流程和战斗计算模块使用 JavaScript。

```sh
cd /workspace/MYGAME
npm ci --ignore-scripts
npm run dev
```

开发服务器默认监听 `0.0.0.0:5173`，可通过 `PORT` 改变端口。无需 API 密钥。正式部署先执行 `npm run build`，将生成的 `dist/` 作为静态站点发布；资源使用相对路径，可部署到子目录。`npm run preview` 在 4173 端口检查打包结果。

首页、商店和属性面板使用 HTML/CSS；进入战斗时才加载 Phaser。战场默认使用 WebGL，不可用时回退 Canvas。引擎负责角色交互、弹道、浮字和粒子，战斗计算保持独立。

## 打包到自己的服务器

运行 `npm run package:deploy`，会先构建，再在 `releases/` 生成 `MYGAME-server-日期.zip`、同内容的 `.tar.gz` 和压缩包 SHA-256 校验文件。打包机器需要 Node.js、现有项目依赖和 Python 3；目标服务器只需要 Node.js 22.12+，无需安装 npm 依赖。

解压后进入 `MYGAME-server`，执行 `sh start.sh 8080` 或 `node server.mjs --port 8080`。支持 `PORT`、`HOST` 环境变量。部署包包含预压缩静态资源、独立服务器、systemd/Nginx 示例和 [部署说明](deploy/DEPLOY.md)，不使用 GPT 托管。

`node scripts/deploy-check.mjs releases/MYGAME-server-日期.zip` 会从实际压缩包解压并检查启动、端口、压缩、缓存、路径访问和浏览器战斗，需要系统 Chromium、Python 3、tar、sha256sum。此验证使用自己的 5291 端口，可通过 `DEPLOY_TEST_PORT` 修改。

## 自动更新自己的服务器

已提供 GitHub Actions 工作流：推送到 `main` 后运行逻辑测试、部署回退测试、构建和真实浏览器部署包检查，再上传构建产物。配置好服务器和仓库 Secrets，并将 Repository variable `MYGAME_DEPLOY_ENABLED` 设为 `true` 后才会自动部署。仅修改本地代码不会触发更新。

同时设置 Repository variable `MYGAME_PUBLIC_URL` 为玩家使用的完整网址（包含协议与端口）。部署后，GitHub runner 会从公网检查健康、commit/releaseId、JS/CSS，以及真实浏览器开局、战斗、暂停和刷新后的存档恢复。检查使用独立浏览器，不接触玩家存档。服务器切换或健康检查失败会自动回退；公网验收失败会令工作流失败，但不会仅因外部网络异常回退本机健康的版本。

将 [SSH AI 执行说明](deploy/automation/SSH_AI_TASK.md) 交给已经连接服务器的 AI，可完成现有安装迁移、专用 SSH 密钥、GitHub Secrets、部署开关与端到端验收。流程使用版本目录切换和失败回退；重启有短暂中断，玩家刷新后获取新版。服务器无需 GitHub 或 GPT 登录。

`python3 -m unittest discover -s tests -p 'test_deploy.py' -v` 验证发布校验及失败恢复，不会连接或修改真实服务器。上线后的 `/_version` 返回构建版本和提交号，便于判断更新是否实际生效。

## 已有页面与操作

- 首页：开始远征、继续存档、设置、玩法说明、独立界面预览。
- 初始选择与招募：最多随机三选一，剩余不足三名则全部展示；初始英雄之外，第 1–4 层开战前各招募一名，不重复、不替换。
- 战前准备：查看阵容、手动或推荐分配技能点；有剩余点数时可补齐或保留后开战。
- 演示战斗：两队各五个位置，前排靠近中间；血量/法力及回复、攻击进度、弹道、技能冷却、吟唱与眩晕、逐技能托管/自动/点击释放、护盾与命中反馈、状态倒计时和实时属性。首版 40 秒后停止补怪并清场；死亡留空、2 秒一批补满空位。
- 战后商店：四件商品、付费刷新、购入穿戴、替换对比、出售、跨角色转移/交换、站位调整。
- 宝箱：通关后在商店上方直接显示三件奖励，与队伍同屏；允许刷新其中一个选项一次。领取或出售后，奖励区切换为商店商品。继续未领取奖励的存档时仍显示三选一。
- 旅途强化：第一层宝箱处理后，可选「坚韧共鸣」，全队生命上限与施法后的防御状态增强，后招募英雄同样生效。
- 结算：二十层完成或全队失败后展示结果。

首页的「浏览界面」可以直接进入招募、五人战斗、满编商店、宝箱与结算，**不会覆盖正常远征存档**。

## 第一轮试玩

1. 点击「开始远征」，选择初始英雄，再选择第一层加入的同伴。
2. 在准备页点击英雄“成长”手动加点或按推荐补点，再进入战斗，观察攻击进度、弹道、血蓝条和技能冷却；点击暂停可休息或返回首页。
3. 通关后，上方显示宝箱三选一，下方保留队伍。点击装备再点空槽，或拖动装备图标到空槽，直接穿戴；放到占用槽才弹出局部对比并要求确认。也可点击“出售所选”。
4. 商店购买使用相同操作。点击已穿戴装备可在小浮窗中出售或选择转移；拖动已穿戴装备可转移，放到占用槽先确认交换。金币不足或违反橙装限制的位置标红，操作不扣款。拖动英雄名字或依次点击两名英雄，可交换站位，装备跟随英雄。
5. 处理宝箱后进入下一层，直到胜利或失败。招募、准备和商店上方的流程条会提示当前步骤。

要直接体验新战斗机制，可使用「浏览界面 → 战斗界面」：预置五名正式英雄、正式白蓝紫装与坚韧共鸣。正常远征中白蓝紫装来自商店/宝箱、红装通过合成取得；第一层商店可以领取示例强化。角色、价格、关卡时长和难度仍为临时配置。详细规则见 [战斗契约](docs/COMBAT.md)。

## 已确认的装备和界面规则

- 无背包；每人四个装备槽、最多一件橙装。普通同名装备可以叠加。
- 装备和站位只能在商店调整。空槽直接交易，替换或交换占用槽需确认；替换旧装备会按半价出售，交换不产生金币。拖出目标、Escape 或触屏取消不会交易。鼠标和触屏共用 Pointer Events，拖动图标/名字时靠近页面上下边缘会自动滚动，普通文字区域可正常触屏滚动。
- 金币来自击杀；没有额外通关金币。刷新费用暂定 `80 + 本轮已刷新次数 × 40`，出售比例暂定 50%。价格及概率均待正式平衡。
- 当前固定78件白蓝紫红装备、73配方；点击已穿戴材料查看路线并支付合成费。旧绿/橙仅兼容旧档，新橙装和供给尚未接入。
- 电脑的生命/法力当前值、上限和每秒回复显示在战场角色下方；手机横屏保留血蓝条和当前/上限，回复与精确数值放当前英雄详情。
- 属性使用一组按钮统一切换：主要页为攻击力、法强、攻速、技能急速、暴击率、全能吸血、物抗、魔抗；其他属性放在次要页。两页保持相同底栏高度。

## 存档与暂停

进度保存在当前浏览器的 `localStorage`，键为 `squad-expedition.save.v1`。招募选项、商店商品、宝箱结果、单项刷新次数与装备交易均立即保存。离开战斗后继续游戏从该关开战前恢复，不保存战斗中的每一帧。

切换到后台会暂停；回来后需要点击继续。电脑悬停技能/装备约 400ms 打开局部说明，移动到说明内可继续阅读，点击可固定；手机点击打开。说明出现时暂停模拟、弹道、浮字和粒子，关闭只解除说明暂停，不覆盖后台/其它暂停原因。技能显示1–4，图标主体查看说明，右上圆钮按托管/自动/点击循环，默认全托管；点击模式使用独立“释放1…4”按钮，也可用1–4键对当前英雄下令。模式设置随英雄保存。手机转竖屏暂停，回横屏后点击继续。关闭界面动效不会改变计算结果。无账号、云同步或联网功能。

## 验证

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run test:browser
npm run test:shop
npm run test:battle
npm run test:engine
npm run build
```

逻辑测试使用 Node 内置测试器。浏览器验证使用已锁定版本的 `playwright-core` 和系统 Chromium（本云环境为 `/usr/bin/chromium`），不会自动下载浏览器。其他机器可通过 `CHROMIUM_PATH` 指定已安装的 Chromium；没有浏览器时可运行类型检查、逻辑测试和构建。页面、引擎、商店、战斗交互脚本分别自启并清理自己的 5188/5189/5193/5194 端口服务器，截图和引擎测试指标写入被 Git 忽略的 `test-results/`。云端无头浏览器的帧率仅用于本环境比较，不能代表玩家设备性能。

这是可玩的基础原型，不是完成平衡的游戏：五英雄同预算平衡、更多英雄/状态、完整强化池、其他橙装效果、美术、音效、平板适配和桌面打包留待后续。

商店交互验证覆盖 2560×1440 鼠标与 390×844 Chromium 原生触屏模拟，包括跨屏拖动、取消、金币/橙装限制、替换与交换确认、英雄换位和存档恢复。手机商店采用两列队伍布局；战斗横屏在 844×390、740×360 检查十单位同屏、44px 操作区、当前英雄详情、属性视图和旋转暂停。完整竖屏战斗和平板专用布局仍未制作；Chromium 模拟不等于全机型真机验收。

战斗反馈区分普攻、技能、暴击、治疗、护盾吸收和吸血；护盾伤害始终蓝色，穿盾生命损失另记，吸血/全能吸血绿色并标记来源，自然回复按一秒汇总。重复同类结算约 300ms 内合并，每单位最多两组、手机最多十二组浮字，不改变实际伤害与触发。具体边界见 [战斗契约](docs/COMBAT.md)。

### 战斗 V2 操作

点英雄，再点敌人即可保存优先位置及邻位；击杀后按该英雄选择的策略自动寻找下个目标。五种策略为命中最高、生命比例最低、当前生命最低、最近和最远；位置偏好随本局存档保存。英雄下方数字显示实际目标，左下显示保存偏好，可单独清除。

挑战传送带有空位时点击“加入”立即上场，满员或清场时不能加入；击杀才给奖励。桌面左下英雄/右下敌人详情；手机横屏在技能装备、属性、战术、敌人之间切换，重复点属性切主要/次要。技能/装备说明仍会暂停。

`node scripts/battle-v2-check.mjs` 检查真实鼠标/触屏指令、即时挑战与存档恢复。实现边界及可调整参数见 [战斗 V2](docs/BATTLE-TACTICS-V2.md) 和 [COMBAT](docs/COMBAT.md)：当前已按D035/D037接入78件装备、五名正式英雄及完整升级，保留精准/闪避与距离命中。

战斗视觉已按概念图修正为地牢背景与青红信息卡，头像/图标仍为文字占位。[查看真实运行截图与改前对照](docs/design/battle-v2/README.md)。`node scripts/battle-visual-check.mjs` 检查桌面/触屏布局并重建截图；该检查已随 `test:battle` 执行。

三模式施法与真实界面见[实现记录](docs/design/casting-modes/README.md)；`node scripts/casting-mode-check.mjs`验证四尺寸独立切换、手动普通技能、暂停和保存恢复。托管已覆盖五名正式英雄专属机制；全套英雄平衡仍待校准。

英雄面板的“成长”入口支持关外加点、推荐补点和16级后的属性三选一。固定八项成长持续，法强只由装备增加。五名均从正常招募取得；普通技能4级、大招3级，二级学习不同技能，六级前普通最多3级，大招5/10/15级解锁。旧存档自动迁移英雄并保留装备/成长选择。完整说明与验证边界见[英雄接入](docs/heroes/RUNTIME.md)。
