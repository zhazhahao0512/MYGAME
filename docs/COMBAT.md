# 战斗基础与扩展契约

这是一套已接入页面的战斗基础，内容和数值仍是示例。`src/battle.js` 协调模拟，`src/combat/` 提供属性、单位、状态、触发队列和内容定义。Phaser 只负责显示，不判断伤害。

## 单位与来源

英雄、普通怪和首领由同一个 `createUnit()` 创建，拥有相同的基础属性、最终属性、来源集合、技能、冷却、状态、触发器、资源和行动字段。敌我差别是阵营与内容配置。普通怪目前没有主动技能，首领有一个带吟唱的重击；可以直接配置同结构技能。

装备只在商店变更，开战时根据当前阵容重建单位。单位的 `sources` 用来源 ID 管理属性修改及规则覆盖；替换同一 ID 更新该来源，移除来源后重新计算，不能反向减去旧数值。战斗中的临时状态不会写进关卡存档。

`resolveStats()` 对每个属性使用：

```text
(基础值 + 固定加值之和) × (1 + 百分比加值之和) × 独立倍率之积
```

- `flat`：固定加值；`percent`：比例加值，例如 `0.2` 表示 +20%；`multiply`：独立倍率，例如 `1.2`。
- `override`：覆盖计算值，优先级较高的生效；相同优先级按完整来源 ID、修改 ID 的字符串顺序确定，最后一项生效。
- 最后统一约束：生命至少 1，攻速至少 0.05，移动速度至少 1，暴击最多 100%，韧性最多 60%，减伤最多 80%；其他现有属性非负。这些上限是当前实现规则，可调整。
- 最终属性只在来源改变时重算。生命/法力上限增加不会凭空回复资源；上限降低时截断超出部分。

规则覆盖使用相同的优先级机制，当前消费 `attackTarget` 和 `skill.Q.cost/cooldown/castTime/priority/target` 等技能键。它们可以由装备或状态来源修改，不需要直接修改英雄模板。已发出的攻击、已经开始的吟唱保留启动时确定的数据；下一次行动使用最新规则。

```js
setSource(unit, 'equipment:example', {
  modifiers: [{ id: 'speed', stat: 'attackSpeed', op: 'percent', value: .2 }],
  rules: [{ id: 'aim', rule: 'attackTarget', value: 'slot3', priority: 10 }],
});
removeSource(unit, 'equipment:example');
```

## 状态

状态定义包含 `id/name/duration/stacking/modifiers/rules`，可选 `maxStacks/control/shared`。时间统一以 20ms 固定步计算。

- 默认按“状态 ID + 施加者单位 ID”区分来源；`shared` 可配置为全来源共用一个状态槽。
- `refresh` 刷新持续时间，不加层；`stack` 加层至上限并刷新整组时间；`replace` 用新定义替换旧状态。
- 固定值和百分比加值按层数相乘，独立倍率按层数乘方。当前示例仅用固定值。
- 到期和主动移除都会删除对应来源并重算。状态来源不会串到后来生成的同位置怪物。
- 目前控制类型为眩晕：不能开始普攻/施法，立即取消正在吟唱的技能；持续时间按 `基础时长 × (1 − 韧性)` 确定。已发出的攻击继续飞行和结算。
- 没有状态抗性。独立每层计时、持续伤害、驱散分类、免疫与更多控制类型尚未实现。

## 技能执行

每个技能定义消耗、冷却、初始冷却、优先级、吟唱时长、目标规则和效果列表。效果目前支持伤害、治疗、护盾、施加状态；伤害效果可配置物理/魔法、攻击力/法强系数、固定值、飞行时间、能否闪避/暴击，以及命中后的状态。

1. 自动行动按优先级从高到低检查，同优先级按技能槽位顺序。每次施放前重新检查存活、控制、吟唱、冷却、法力和目标。查询是否可用不会消耗随机数。
2. 开始施法时扣法力并开始冷却。瞬发技能不改变普攻冷却，可连续释放；吟唱占用行动，直到释放或被打断。
3. 吟唱被打断不退法力、不返还冷却。目标无效时，`retarget: 'release'` 在释放时重新选目标；`none` 取消失效目标，没有有效目标则落空。
4. 伤害弹道在发出时快照命中、暴击、伤害、抗性与吸血系数。到达时检查目标的唯一编号与存活，再按当前护盾和生命扣除；不会改打同位置新怪。命中附带状态在落点结算。
5. 完成释放后发出 `cast` 事件；强化带来的施法后增益用于之后的行动，当前已经发出的弹道不会重新计算。已经开始的冷却和吟唱不会因急速变化重排。

治疗按施放者治疗增强计算，护盾按施放者护盾增强计算。吸血基于实际生命损失，不含护盾吸收或过量伤害。普攻默认可闪避、可暴击；当前伤害技能默认必中、不暴击，定义可覆盖这两项。专注与移动速度决定命中率 `clamp(专注 / 移速, 0, 1)`。

## 触发顺序与边界

每步依次处理：计时到期进入清场 → 状态到期 → 已发出攻击按创建顺序结算 → 判定失败/清场成功 → 独立补怪 → 单位回复和行动。双方同一步全部阵亡按失败处理。

每次伤害先完成护盾和生命变化，再依次入队 `hit`、可选 `critical`、`damaged`、可选吸血 `heal`、击杀 `kill` 和 `death`。死亡与击杀奖励立即标记一次，入队的反应不能重复发奖。`damaged.amount` 是实际生命损失，完全被护盾吸收不触发当前“受到生命伤害”效果。

- 事件按先入先出处理。匹配顺序固定为单位顺序，再被动、装备槽、强化的配置顺序。反应产生的新事件排到队尾，不递归调用事件分发。
- 触发器指定事件、与事件源/目标的关系、独立冷却和效果列表。死亡单位不再响应普通触发事件；死亡事件可扩展独立处理，目前没有复活效果。
- 每个根事件最多 128 个事件，链深最多 8，等待队列最多 512；同一单位的同一触发器不能在同一条路径上再次进入。独立攻击拥有独立预算。
- 超过边界的额外触发被抑制，计入 `battle.events.suppressed`。这是明确的结算限制；不影响独立普攻的正常结算。最近 256 条事件保留作调试记录，视觉事件另有独立的 256 条上限。
- 触发产生的追加伤害目前即时结算，不生成新弹道；所有正常攻击与伤害技能仍按飞行时间结算。

第一层宝箱处理后，商店可以选择本次远征的示例强化，也可以直接继续。后招募英雄继承强化。当前只接入一种强化，后续多层三选一的正式强化池尚未制作。

从首页「浏览界面 → 战斗界面」可直接体验五人示例队伍，内含磐石、三种橙装和坚韧共鸣；该入口不会覆盖正常存档。角色下方显示吟唱进度和状态，底部属性实时更新。其他英雄仍使用通用演示技能，其他橙装仍保留特殊效果占位。

## 视觉反馈与吸血展示

`EffectEvent` 保留 source/target 唯一 ID、来源类别/技能标识，以及 damage 的 `hpLoss` 和 `shieldLoss`。伤害事件 `amount` 现表示实际生命损失，完全被盾吸收时为 0；渲染器分别显示生命伤害与蓝色盾伤，暴击命中护盾也保持蓝色并带“暴击”标记。普攻浅色、技能青色并带技能键、生命暴击金色、闪避灰色；颜色表示反馈类别，不代表物理/魔法伤害类型。

吸血结算仍使用发射快照：普攻 `(吸血 + 全能吸血)`，伤害技能/伤害触发效果只用全能吸血，乘以实际生命损失及治疗增强；不含护盾吸收和过量伤害。死亡来源不恢复，满血不制造治疗，过量恢复截断到缺失生命。两种吸血同时存在时保持一次真实 heal 事件，视觉标记“吸血/全能”；单一来源分别标记“吸血”“全能”，均为绿色。普通治疗标“治疗”，保留技能/触发来源。自然回复继续原有逐步结算且不发 heal 触发，只按每秒汇总实际恢复量发布柔绿色“回复”表现。

`src/renderer/feedback.js` 仅聚合表现：同来源/目标实例/来源定义/结果类别/暴击类别的 300ms 窗口累计实际数值，最后格式化；不同英雄、重生 ID、暴击与普通、治疗与伤害、护盾增益与吸收不混算。每单位最多两组，电脑全场上限 24（当前十单位实际不超过 20），手机 12，优先保留选中英雄及暴击；单组 700ms 后消退。暂停沿用模拟 tick 冻结合并与动画。视觉裁剪不修改实际战斗事件、RNG、生命与资源。

`tests/feedback.test.js` 验证护盾/生命拆分、吸血快照与实际恢复、回复不新增触发、合并隔离/预算和战斗结果一致；`npm run test:battle` 检查实际渲染颜色、说明暂停、独立 R、键盘与鼠标、触屏横屏及旋转。
