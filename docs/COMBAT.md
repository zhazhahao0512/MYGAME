# 战斗基础与扩展契约

这是一套已接入页面的战斗基础，内容和数值仍是示例。`src/battle.js` 协调模拟，`src/combat/` 提供属性、单位、状态、触发队列和内容定义。Phaser 只负责显示，不判断伤害。

## 单位与来源

英雄、普通怪和首领由同一个 `createUnit()` 创建，拥有相同的基础属性、最终属性、来源集合、技能、冷却、状态、触发器、资源和行动字段。敌我差别是阵营与内容配置。普通怪目前没有主动技能，首领有一个带吟唱的重击；可以直接配置同结构技能。

装备只在商店变更，开战时根据当前阵容重建单位。单位的 `sources` 用来源 ID 管理属性修改及规则覆盖；替换同一 ID 更新该来源，移除来源后重新计算，不能反向减去旧数值。战斗中的临时状态不会写进关卡存档。

`resolveStats()` 对每个属性使用：

```text
(基础值 + 固定加值之和) × (1 + 百分比加值之和) × 独立倍率之积
```

- `flat`：固定加值；`percent`：比例加值，例如 `0.2` 表示 +20%；`multiply`：独立倍率，例如 `1.2`。
- `override`：覆盖计算值，优先级较高的生效；相同优先级按完整来源 ID、修改 ID 的字符串顺序确定，最后一项生效。
- 最后统一约束：生命至少 1，攻速至少 0.05，移动速度至少 1，暴击最多 100%，韧性最多 60%，减伤最多 80%；其他现有属性非负。这些上限是当前实现规则，可调整。
- 最终属性只在来源改变时重算。生命/法力上限增加不会凭空回复资源；上限降低时截断超出部分。

规则覆盖使用相同的优先级机制，当前消费 `attackTarget` 和 `skill.Q.cost/cooldown/castTime/priority/target` 等技能键。它们可以由装备或状态来源修改，不需要直接修改英雄模板。已发出的攻击、已经开始的吟唱保留启动时确定的数据；下一次行动使用最新规则。

```js
setSource(unit, 'equipment:example', {
  modifiers: [{ id: 'speed', stat: 'attackSpeed', op: 'percent', value: .2 }],
  rules: [{ id: 'aim', rule: 'attackTarget', value: 'slot3', priority: 10 }],
});
removeSource(unit, 'equipment:example');
```

## 状态

状态定义包含 `id/name/duration/stacking/modifiers/rules`，可选 `maxStacks/control/shared`。时间统一以 20ms 固定步计算。

- 默认按“状态 ID + 施加者单位 ID”区分来源；`shared` 可配置为全来源共用一个状态槽。
- `refresh` 刷新持续时间，不加层；`stack` 加层至上限并刷新整组时间；`replace` 用新定义替换旧状态。
- 固定值和百分比加值按层数相乘，独立倍率按层数乘方。当前示例仅用固定值。
- 到期和主动移除都会删除对应来源并重算。状态来源不会串到后来生成的同位置怪物。
- 目前控制类型为眩晕：不能开始普攻/施法，立即取消正在吟唱的技能；持续时间按 `基础时长 × (1 − 韧性)` 确定。已发出的攻击继续飞行和结算。
- 没有状态抗性。独立每层计时、持续伤害、驱散分类、免疫与更多控制类型尚未实现。

## 技能执行

每个技能定义消耗、冷却、初始冷却、优先级、吟唱时长、目标规则和效果列表。效果目前支持伤害、治疗、护盾、施加状态；伤害效果可配置物理/魔法、攻击力/法强系数、固定值、飞行时间、能否闪避/暴击，以及命中后的状态。

1. 英雄按有效点击指令→自动释放→托管释放处理；普通自动和敌人沿用定义优先级，同优先级按技能槽位顺序。托管按下文R043策略选择。每次施放前重新检查存活、控制、吟唱、冷却、法力和目标。查询是否可用不会消耗随机数。
2. 开始施法时扣法力并开始冷却。瞬发技能不改变普攻冷却，可连续释放；吟唱占用行动，直到释放或被打断。
3. 吟唱被打断不退法力、不返还冷却。目标无效时，`retarget: 'release'` 在释放时重新选目标；`none` 取消失效目标，没有有效目标则落空。
4. 伤害弹道在发出时快照命中、暴击、伤害、抗性与吸血系数。到达时检查目标的唯一编号与存活，再按当前护盾和生命扣除；不会改打同位置新怪。命中附带状态在落点结算。
5. 完成释放后发出 `cast` 事件；强化带来的施法后增益用于之后的行动，当前已经发出的弹道不会重新计算。已经开始的冷却和吟唱不会因急速变化重排。

治疗按施放者治疗增强计算，护盾按施放者护盾增强计算。吸血基于实际生命损失，不含护盾吸收或过量伤害。普攻默认可闪避、可暴击；当前伤害技能默认必中、不暴击，定义可覆盖这两项。专注与移动速度决定命中率 `clamp(专注 / 移速, 0, 1)`。

## 触发顺序与边界

每步依次处理：计时到期进入清场 → 状态到期 → 已发出攻击按创建顺序结算 → 判定失败/清场成功 → 按推荐位置批次补怪 → 单位回复和行动。双方同一步全部阵亡按失败处理。

每次伤害先完成护盾和生命变化，再依次入队 `hit`、可选 `critical`、`damaged`、可选吸血 `heal`、击杀 `kill` 和 `death`。死亡与击杀奖励立即标记一次，入队的反应不能重复发奖。`damaged.amount` 是实际生命损失，完全被护盾吸收不触发当前“受到生命伤害”效果。

- 事件按先入先出处理。匹配顺序固定为单位顺序，再被动、装备槽、强化的配置顺序。反应产生的新事件排到队尾，不递归调用事件分发。
- 触发器指定事件、与事件源/目标的关系、独立冷却和效果列表。死亡单位不再响应普通触发事件；死亡事件可扩展独立处理，目前没有复活效果。
- 每个根事件最多 128 个事件，链深最多 8，等待队列最多 512；同一单位的同一触发器不能在同一条路径上再次进入。独立攻击拥有独立预算。
- 超过边界的额外触发被抑制，计入 `battle.events.suppressed`。这是明确的结算限制；不影响独立普攻的正常结算。最近 256 条事件保留作调试记录，视觉事件另有独立的 256 条上限。
- 触发产生的追加伤害目前即时结算，不生成新弹道；所有正常攻击与伤害技能仍按飞行时间结算。

## 视觉反馈与吸血展示

`EffectEvent` 保留 source/target 唯一 ID、来源类别/技能标识，以及 damage 的 `hpLoss` 和 `shieldLoss`。伤害事件 `amount` 现表示实际生命损失，完全被盾吸收时为 0；渲染器分别显示生命伤害与蓝色盾伤，暴击命中护盾也保持蓝色并带“暴击”标记。普攻浅色、技能青色并带技能键、生命暴击金色、闪避灰色；颜色表示反馈类别，不代表物理/魔法伤害类型。

吸血结算仍使用发射快照：普攻 `(吸血 + 全能吸血)`，伤害技能/伤害触发效果只用全能吸血，乘以实际生命损失及治疗增强；不含护盾吸收和过量伤害。死亡来源不恢复，满血不制造治疗，过量恢复截断到缺失生命。两种吸血同时存在时保持一次真实 heal 事件，视觉标记“吸血/全能”；单一来源分别标记“吸血”“全能”，均为绿色。普通治疗标“治疗”，保留技能/触发来源。自然回复继续原有逐步结算且不发 heal 触发，只按每秒汇总实际恢复量发布柔绿色“回复”表现。

`src/renderer/feedback.js` 仅聚合表现：同来源/目标实例/来源定义/结果类别/暴击类别的 300ms 窗口累计实际数值，最后格式化；不同英雄、重生 ID、暴击与普通、治疗与伤害、护盾增益与吸收不混算。每单位最多两组，电脑全场上限 24（当前十单位实际不超过 20），手机 12，优先保留选中英雄及暴击；单组 700ms 后消退。暂停沿用模拟 tick 冻结合并与动画。视觉裁剪不修改实际战斗事件、RNG、生命与资源。

`tests/feedback.test.js` 验证护盾/生命拆分、吸血快照与实际恢复、回复不新增触发、合并隔离/预算和战斗结果一致；`npm run test:battle` 检查实际渲染颜色、说明暂停、独立 R、键盘与鼠标、触屏横屏及旋转。

## R024 · 战斗 V2 当前实现

已依据 [D009](decisions/D009-battle-v2-implementation.md) 接入；下列是可调整的首版默认。

- `src/combat/tactics.js` 提供五策略、指令标准化、稳定候选排序、怪物推荐位置和刷新参数。`Battle` 保持唯一结算入口，Phaser 不结算命中或奖励。
- 英雄/怪物同构新增 `tactics/targetId/targetRule/reward/challenge/enemyType`；玩家指令仅挂我方成员，怪物继续使用内容规则。存档的 `member.tactics` 只有策略与位置，不保存临时目标 ID。旧存档缺失/无效指令恢复默认，商店换位跟随完整英雄对象。
- 默认命中最高；其它为生命比例最低、绝对生命最低、最近、最远。偏好位置左右各一格先过滤，无区域候选则回退全场；相同分数按距离、位置、单位 ID 稳定排序。最高命中读取现行 `hitChance(focus,move)`，不消耗随机数；**精准/闪避、距离减益和四类伤害仍未迁移**。技能当前继承锁定，不宣称已实现按每个技能不同精准修正重排。
- 目标有效时保持，死亡/失效、玩家切策略/清偏好或来源覆盖规则变化时重选。手动点敌人保存位置并设置当前实例目标；不重置行动冷却/法力，不改变已发射攻击或已开始吟唱的目标。来源 `attackTarget` 覆盖仍保留；特殊目标范围与完整强制转火机制随内容扩展。
- 首版每关 40 秒，开局五敌，6 秒一批、每批最多 2 个、在场不超过五个。死亡位置保留，普通怪按推荐位置选择；首领仍在 5/10/15/20 层只出现一次。血量较旧原型提高，实际强度/击杀时间还需试玩校准。
- 三张可选挑战卡由独立候选随机源产生，不污染未接受挑战时的战斗命中随机序列；首次展示期限错开为 12/16/20 秒，之后各 12 秒。点击只入队、不扣金币、不即时刷新/发奖；待入场最多 3 个，可取消。兼容空位的挑战优先占用当批名额；前排满不会堵塞可进后排的挑战。所有计时跟随模拟暂停。
- 计时结束先进入清场，再处理当步伤害，禁止同一步入场；清除未入场候选/请求，无奖励，仍需清完已在场敌人。击杀奖励仅发一次；旧弹道绑定旧 ID，绝不命中新实例。
- 桌面只展示当前英雄与查看中的敌人；实际目标数字与保存位置分开。点英雄进入一次下令，点敌人后退出；仅查看、其它控件、Esc/空白可取消。技能/装备/敌技能说明沿用暂停；仅查看常驻敌面板不暂停。手机底栏以技能装备/属性/战术/敌人切换，属性重复点击切主要/次要。

新增 `tests/tactics.test.js` 覆盖策略、锁定、保存/换位、覆盖失效、刷新时序和队列边界；`scripts/battle-v2-check.mjs` 用真实 Canvas、鼠标和触屏检查指令/队列与存档。旧说明暂停、手动大招、护盾/吸血反馈和商店拖动继续回归，最新结果见 R024。


## R043 · 逐技能三模式当前实现

[D022](decisions/D022-casting-implementation.md)授权本轮接入；策略代码为`src/combat/casting.js`，动作执行仍由Battle负责，保留原伤害/目标/快照规则。

- 英雄每个主动技能独立`skillModes`，值为`managed/auto/manual`，默认全managed。敌人维持既有机械自动；旧`auto`大招字段不再控制英雄施法。新招募、旧存档缺字段或无效字段默认托管；设置跟随英雄实例、换位、跨关和保存读取。战中读档仍按既有契约重开本关，不保存临时战斗/指令。
- 混搭仲裁：有效点击指令、普通自动、托管，最后普攻。瞬发可在同一步连续释放，每次重算真实蓝量/状态；吟唱占用行动。普通自动不执行留蓝与收益过滤，仍守硬合法性。
- 点击：四技能均可请求；空闲立即启动，忙于吟唱则只保存一条最多1.5秒模拟时间的指令，执行前再次校验。缺蓝/冷却/控制不排队；新有效指令替换旧指令；待放按钮禁重复。死亡/控制/结束/模式变化清理，暂停不推进时钟；已发弹道和普攻冷却不算技能占用。界面释放仅解除说明暂停，后台/手动/模态/旋转暂停仍阻止释放；1–4键只操作当前英雄，屏蔽长按/输入框/模态。
- 托管每次原生20ms行动机会读取当前有效技能定义和装备最终属性，不增加独立随机调用；`getSkill`支持可选`rank/ranks`（0未学、逐档覆盖），先覆盖等级再套实时规则。现有英雄尚无正式技能加点系统，默认一级效果；本轮没有把英雄等级当技能等级自动抬升。
- 首版估算覆盖现有直接伤害、有效治疗、护盾与固定双抗/攻速状态；根据当前命中期望、抗性、剩余HP/盾、施法可能占用普攻的时间、实际目标数比较。低于等于35%生命且受压的治疗/护盾进入救急；高可信度危险目标收割/及时打断其次，输出核心第三，补充防护第四。不同用途按模板定义优先级，不用额外等级加分。估算不改变真实结算，不读取在途弹道已抽出的命中/暴击结果。
- 准备窗口8秒；未来收益按`value/(1+剩余冷却/8)`折扣，当前蓝不足覆盖候选消耗时，同用途比较折扣收益/蓝耗；零蓝技能不除0。保留一个候选，出现更紧急需求或同层同用途收益高25%以上才改计划，失效则解除。
- 缺蓝技能可以成为储备目标；储备`max(0,消耗−保证回蓝×剩余冷却)`。回蓝取开战永久值与当前值较小者，不预支临时增益/击杀/随机回复；其它托管技能付款后须保留此量，救急、普通自动和玩家指令可突破。最大蓝不足、零回复且无力支付、无有效目标/收益则解除。等待仍普攻，40秒仅切清场，不无条件清蓝。
- 原型尚无岚牙的充能附伤/大招接管，未实现预设多技能连招搜索、攻击特效/精准增益专属收益适配；新增正式英雄需补对应模板和机制测试。本轮不改英雄面板、技能伤害、装备或新精准，不宣称托管为所有构筑最优或完成平衡。

## 全部47件装备运行契约（R047）

[D024](decisions/D024-equipment-runtime.md)记录本次实施授权。固定目录`src/equipment.js`含12白/21蓝/14紫与35条配方；`model.js`提供固定池抽选、合成预览/原子提交、旧存档货币迁移。新池没有绿装、旧模板、未设计的红橙；旧存档仍可穿戴/转移/出售，其原属性与三件橙色示例触发器保留。

- `equipmentModifiers`把正式装备attackSpeed作为普通percent，固定/乘风/穷追相加后作用于英雄基础频率；其他属性平加。同名效果按英雄的effectId集合去重，不因穿戴两件而增加计数或触发份数。
- `Battle.fire`在普通攻击发射时构造三重打击候选快照，`settle`仅命中后增加一次basicHit计数；技能、附伤和触发反击不进入这个入口。附伤在本体后仅对存活原ID结算，共享本体hit，不另抽RNG。禁止crit/两类vamp及hit/critical事件，保留正常damaged、伤害归属与死亡。
- 血性只在本体伤害与吸血之前读当前HP＜50%，加3%本体吸血；攻击发射时的普通吸血/全能吸血/治疗增强仍保留。狠厉只给普攻本体暴击倍率加0.15；卸力只给发射时的物理普攻本体在护甲等减免后乘0.92，在入盾前完成。背水通过独立modifier来源动态加/移除12攻击，不修改在途快照。
- 战意盾自有remaining/expiry，第四次有效命中补至30/3秒；承伤先扣该有限期限盾，剩余再扣原有无期限盾，到期只删自身余量。回流为3/秒持续3秒自然回复，不立即heal；乘风+20%与穷追每层+4%/最多3层均3秒，后者换主目标立即清空且旧目标在途命中不重建。
- `release`为余韵绑定主目标首伤段、该段释放时AP快照，只有一份25＋5%AP魔伤；成功释放进入12秒独立冷却，暂停冻结、跨战重置。首段miss/被提前击杀则无收益、不退充能。纯治疗/盾/增益和释放前取消不消费。当前AOE沿原目标数组首位为主目标，后续持续/引导内容需自行声明绑定段。
- `dealDamage`按实际HP＋shield损失记target.contributors和伤害所属英雄；导流在真实死亡时按唯一目标只结算一次。6秒含边界，受益者须存活、有法力和该被动，恢复15封顶。ownerId链支持明确归属的单位，纯治疗/加盾不记助攻；非死亡退场不发奖励。新怪新ID不会继承贡献。
- 每战重新初始化计数/充能/盾；保存战前装备，不保存临时被动。单位共有equipment/contributors/takedownSettled字段，现有英雄/怪物统一结构保持。
