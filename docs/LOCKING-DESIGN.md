# 持续刷怪下的锁敌与出怪结构取舍

2026-10-19，R015。用户担心逐英雄单独写选敌难兼容特殊情况，玩家手调又太频繁，提出对应位置优先或改为前排死亡后整体前移，要求比较自动战斗游戏做法。本轮仅设计，以下推荐尚未确认，不改出怪与战斗代码。

## 推荐结论

保留现有固定位置独立补怪；选敌独立成统一模块，由英雄/技能提供规则。普通攻击默认先选择最前存活敌人，选定后保持到死亡或失效，补怪不自动打断锁定；特殊英雄可以用后排/血量等选择器及不同的重选时机。普通单体伤害技能默认沿用该英雄的有效普攻目标，特殊技能自己选敌。友方治疗、护盾和群攻按自己的目标需求处理。

规则由内容设计者预设，玩家通过选英雄、站位、装备和强化改变打法，不必每轮打开战术编辑器。代码模块独立不等于每个英雄写一个互不相干的算法；先复用少量选择器，实际遇到特殊英雄再增加受约束的条件规则。

这是 R015 的新推荐；R013 曾建议每次出手重选，R014 只把保持锁定作为参考，均未获完整确认。新推荐也不等于已修改当前行为：代码仍每次新攻击调用 `target()`，尚无持续保存的普攻锁定目标。

## 常见自动战斗参考

| 游戏 | 高层机制思路 | 对 MYGAME 的启示 |
| --- | --- | --- |
| 土豆兄弟 | 常规武器通常自动瞄准射程内附近敌人，玩家主要通过移动与构筑影响输出；武器/模式可有差异 | 默认选敌应足够简单可靠，不把每个新怪变成操作负担；其自由移动与我们的固定阵列不同，不能直接照搬距离逻辑 |
| 吸血鬼幸存者 | 目标逻辑常由武器定义：基础魔杖针对近处敌人、飞刀随朝向攻击、大蒜为周身范围效果 | 不必强求所有技能都用同一个目标规则，也不需要玩家实时逐个点选 |
| 云顶之弈等自走棋 | 常规攻击围绕交战目标持续，技能可使用独立目标；具体棋子与版本细节不同 | 区分“首次如何选”和“什么时候重新选”，已有目标不必因每次新怪出现就改变 |
| Super Auto Pets | 基本交战以队伍前方宠物为中心，前方阵亡后后续单位接上，能力可影响其它位置 | 前排接续适合清晰的队列对抗，但原作不是五个位置持续独立刷怪，改编需要重新设计补怪 |

这是已有机制的概括，未作当轮外部资料检索，不声称各版本/武器都完全一致。下方 MYGAME 方案为本项目设计，不是这些游戏的精确算法。

## 三种方案比较

| 方案 | 优点 | 对现有玩法的影响 | 建议 |
| --- | --- | --- | --- |
| 固定位置补怪 + 统一选敌模块 + 默认保持目标 | 保留连续击杀、独立补怪、前后排与英雄差异；玩家无额外操作 | 新增锁定状态与失效校验，重选时机需在说明中明确 | 第一版推荐 |
| 对应位置优先，空位再找其它目标 | 一眼看懂初始分工，输出分散 | 双方都这样时坦克难保护其它位置；本作是前后排横队，不是五条平行战线，5→5 很远；前期英雄不满员还需完整后备顺序 | 可做特殊英雄/阵容规则，不推荐全局默认 |
| 敌方压缩队列，普攻优先当前最前敌人 | 目标集中、战线推进直观；前排承担明确作用 | 需要改刷怪语义、位置变化和动画；若所有技能也只能打前排，会削弱后排针对与选敌差异 | 如果目标改为“突破一条敌阵”则可选，不为降低选敌代码复杂度而直接更换 |

对应位在现有距离设计下的例子：基础精准 95、目标闪避 0，1→1 为 95%；5→5 额外 8 格，远程命中 79%、近战 55%。这不是五条等距线路。若希望对应位互打都同样近，等于重做布局与距离定义，不能悄悄取消已确认距离规则。

## 推荐锁敌流程

把每个行动分为三个问题：**谁有资格、按什么顺序选、什么时候重选**。

1. 取得本次行动有效规则。普通攻击用英雄默认；普通单体伤害技能沿用有效普攻目标；特殊技能的明示规则优先。装备/强化按既有来源规则重算，不修改已发出攻击。
2. 根据阵营、存活与实际行动条件生成候选单位。普攻候选仍是全场存活敌人，不因距离变远直接禁止攻击。
3. 默认普攻已有锁定目标且仍合法时继续攻击；目标死亡/消失/不再合法时才重新排序。规则来源发生变化时使相关锁定重新评估，不一直保留过时规则。
4. 没有有效目标时，按选择器排序：默认前排，特殊英雄可选择后排、绝对生命最低、生命比例最低等。目标相同时使用稳定位置顺序。找不到目标则等待，不凭空扣法力、进入技能冷却或堆积攻击次数。
5. 用唯一单位编号保存锁定，不能只记“第 3 格”。发射后维持原快照与目标编号，原目标死亡不改打新刷怪。技能吟唱途中目标失效时仍按既有技能的释放时重选规则处理，并使用该技能自己的选择器。

重选时机应是少量可配置选项：

- **目标失效再选**：普通战士/坦克的建议默认；选敌时优先前排，之后可继续打当前后排目标，不会因 1 号位补怪中途切回。
- **每次新行动重选**：适合“始终攻击最低血量”或每次随机的英雄；这是明示的角色特性，不让“最低血量”文案与持续锁旧目标矛盾。
- **技能自行选择**：斩杀、群体、治疗等在发动时按技能需求选目标，默认不顺便改掉普攻锁定。技能开始时无普攻目标的普通单体攻击技能，用英雄默认选择器正常选敌，不等普攻先出手。

例：某英雄锁定敌方 3 号后，1 号位补怪，不抢走当前锁定；3 号死亡后，英雄下一次选敌才按自身顺序考虑 1 号。另一名明确“每次攻击最低生命目标”的刺客则可在下次出手选择新目标。两者都无需玩家操作，飞行中的攻击都不换目标。

未来若加入嘲讽/标记等明确要求换目标的效果，再定义它与保持锁定的优先级；当前不新增这类状态，也不以“所有特殊情况”名义预建庞大条件系统。

## 模块如何兼容特殊内容

建议独立选敌模块接收：施放者、行动规则、当前锁定、战场只读状态，输出目标单位编号及选中原因。它负责候选过滤、排序/受控随机与复用锁定；伤害、扣蓝、冷却和特效由原有系统负责。说明预览只查询候选与规则，不抽取战斗随机数或改变锁定。

先提供前排、后排、最低生命、最低生命比例、位置列表、随机等可复用选择器；普通英雄填配置即可。特殊英雄新增小型过滤/排序组合，仍经过同一合法性检查，不能直接绕过结算或改战场。无需为每个英雄复制完整流程，也无需把战斗主循环写成一长串英雄名字判断。

## 若选择前排死亡后前移

应先明确改为敌方队列：死亡时剩余敌人顺序前移，约定补怪延迟后从末尾加入，场上最多五只；多个死亡对应独立入场请求，达到关卡时限后取消未入场补怪，再清掉现存敌人。这里是候选规则，尚未批准。

原固定槽位补怪不能与前移同时照旧执行，否则原死亡位可能已被后排占据。还需明确 Boss 是否前移、后排专长如何变化；单位 ID 不随位置改变，弹道跟随同一个目标，已有伤害快照不因途中移位重算。逻辑位置更新与表现位移共用时钟，高频死亡下避免画面不停跳动。初版若选此方案，建议仅敌方前移，我方保留商店阵型；是否双方前移由用户另行选择。

## 下一步与范围

先选择固定补怪阵列或前移队列，再落地锁敌模块。当前推荐前者，默认普攻保持目标、特殊英雄/技能按规则重选，无需玩家频繁设置。全部仍为提案，未改当前出怪、锁敌和距离机制；其它状态与内容继续随英雄登场设计。
