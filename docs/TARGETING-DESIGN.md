# 普攻与技能锁敌范围提案

状态：2026-10-19，R008 历史提案；无游戏代码改动。**R009 用户已明确普攻可攻击所有位置，下文“近战普攻仅前几个存活敌人”的建议已被替代，不得直接实现。** 最新讨论见[全场普攻、命中与站位设计修订](ACCURACY-DESIGN.md)，技能硬位置限制仍未确认。当前实现仍以 [COMBAT](COMBAT.md) 和 `f98cd2c` 为准。

## 目的与既有约束

用户希望参考暗黑地牢，让普通攻击和技能都有锁敌范围。建议借用“站位决定招式适用性、招式决定可选目标”的思路，保留实时自动战斗、五对五、固定位置独立补怪和计时结束后清场。

双方编号均从中心向外，1 为最前，5 为最后：

```text
我方  [5][4][3][2][1]  |  [1][2][3][4][5]  敌方
```

每个单位保持固定位置和独立生成编号，死亡不自动使队伍向前移动；原位置仍按已有规则补怪。英雄、怪物采用相同的范围定义和检查流程。

## 每个行动独立定义五件事

| 项目 | 含义 | 示例 |
| --- | --- | --- |
| 使用位置 | 自己站在哪些固定位置可以发动 | 任意位置；仅 1、2；仅 3、4、5 |
| 目标阵营 | 可以选哪一方 | 敌方、友方、自身 |
| 锁定范围 | 哪些活单位有资格成为目标 | 敌方固定 3、4、5；最前两个存活敌人 |
| 选择优先级 | 在合法目标中选谁 | 最前、最后、生命比例最低、随机 |
| 目标数量 | 选几个单位 | 单体、最多两个、范围内全体 |

先检查使用位置，再过滤活单位、阵营和范围，最后按优先级选取规定数量。范围决定“能不能打”，优先级决定“先打谁”；不能用“最低血量”绕过范围。相同优先级用位置再用单位编号稳定排序；随机只在真正发动时抽取，查看说明不消耗随机数。

每个普攻、Q/W/E/R 各自配置，不能继续让所有单体技能无条件继承普攻的选敌方式。治疗、护盾也使用这套规则；生命比例最低与当前绝对生命值最低须明确命名，不混用。初版群攻直接选择范围内多个合法单位，暂不引入主目标外溅射规则。

## 固定补怪与近战范围的冲突

若所有近战只能打固定 1、2 号位，敌方只剩 5 号位时可能永远无法清场。建议支持两种明确的范围，技能说明必须写清：

- **固定位置**：例如“敌方 3、4、5 号位”。这些位置空了就没有目标，不擅自改打 1、2 号。
- **存活顺序**：例如“最前两个存活敌人”。按固定位置从前向后排列活单位，取前两个；不是角色实际换位。

例：敌方存活于 1、3、5，最前两个就是 1 和 3；1 阵亡后变成 3 和 5；1 补怪后，下次选敌又变成 1 和 3。此前已经射出的攻击仍追踪原单位编号。

**第一版建议**：普攻不限制自身使用位置，近战普攻打最前一个/两个存活敌人，远程普攻可以覆盖全部；主动技能按需要设置自身位置限制和固定目标位置。每名英雄及普通怪物保留不耗蓝的基础输出途径，避免队友死亡或队伍未满时单纯因范围陷入永久互相等待。

这是为当前连续补怪玩法提出的推荐，尚未确认。范围系统本身不禁止未来做“普攻仅打固定后排”的特殊单位，但需同时设计其它基础攻击或明确的僵局规则。普攻兜底只能解决射程造成的无目标，不保证治疗/护盾等数值组合一定可清场；不能把所有无伤害时段直接当作失败。

若用户想所有范围都严格依赖固定位置，则应先另选死亡补位/清场推进/备用行动方案。自动前移会影响原槽补怪与使用位置，不在本提案中悄悄加入。

## 示例（非正式英雄内容和数值）

| 行动 | 使用位置 | 锁定范围 | 选择与数量 |
| --- | --- | --- | --- |
| 战士普攻 | 任意 | 最前两个存活敌人 | 最前，1 个 |
| 战士盾击 | 1、2 | 敌方固定 1、2、3 | 最前，1 个 |
| 射手普攻 | 任意 | 敌方固定 1–5 | 生命比例最低，1 个 |
| 射手狙击 | 3、4、5 | 敌方固定 3、4、5 | 最后，1 个 |
| 法师横扫 | 3、4、5 | 敌方固定 2、3、4 | 范围内全体 |
| 治疗术 | 2、3、4、5 | 友方固定 1–5 的受伤单位 | 生命比例最低，1 个 |

范围标亮多个位置不代表群攻，必须另外显示“单体 / 最多 N 人 / 全体”。第一版不增加战斗中拖动换位、推拉、嘲讽或尸体占位；以后加入需要单独设计与范围的关系。

## 无目标、施法和命中

1. 不能从当前位置使用时显示“站位不符”；范围内无目标时显示“范围内无目标”。未发动不扣蓝、不开始冷却，自动逻辑继续检查其它技能和普攻。
2. 普攻等待期间不累积多次攻击额度，有合法目标后正常发动一次；遵循已有发射与读条/命中同步。
3. 技能开始施法时锁定目标编号，并保存本次行动的有效范围、选择规则与其它配置；施法时间结束时检查目标仍存活且符合这份范围。存活顺序范围此时按当时活单位重算；未来若加入换位，还需检查当前实际位置。
4. 原目标失效时，仅按技能明确的重选规则在上述合法范围重选；默认沿用现有“释放时可重选”的示例技能。仍无目标则落空，已支付法力和冷却不退。多个目标保持去重；目标减少时不得重复打同一单位来补数量。
5. 真正发射时生成伤害、暴击、吸血等快照。飞行中不因补怪或范围变化换目标；命中时仍校验原单位编号和存活，原目标已死则失效。同一格新怪不会承接旧攻击。
6. 自身位置在施法开始检查；第一版战斗中不能换位，不新增中途站位打断。未来加入位移时再明确中断规则。范围来源在施法过程中变化影响后续新行动，不追溯改变已开始的行动。

## 装备、被动与强化怎样修改

范围属于可修改规则，不能只用一个浮点“射程”代表所有情况：固定 2、4 号位和最前两名活单位并非同一种含义。

建议提供明确操作：覆盖范围类型/基础范围、增加或移除固定位置、调整存活顺序范围的数量、修改自身使用位置、覆盖目标优先级、修改数量。效果说明写具体作用对象，例如“Q 增加可锁定的 4 号位”“普攻可选择最前 3 个存活敌人”。不能让“射程 +1”在两种范围下产生不明确解释。

重算顺序建议为：基础定义 → 按优先级与来源 ID 决定覆盖项 → 合并兼容的扩展 → 应用移除（同位置增减时移除优先）→ 校验位置 1–5 和数量。对错误范围类型的修改在内容校验时报错，不能静默套用。每次来源增减都从基础重新计算，移除装备不影响其它来源。界面显示最终规则及其来源。现有 `resolveRules` 仅支持整项覆盖；这些集合运算是待实现能力。

## 界面与验收建议

- 普攻和技能说明显示两行五个位置标记：“可用站位”“可锁定位置”，加目标数量与优先级；存活顺序范围显示原文及当前实际对应位置。
- 查看说明沿用已有暂停规则，并高亮当前合法目标；不增加持续交织的全场射线。手动 R 同样受范围限制。
- 商店换位即时预览哪些技能可用；存在失效技能时提示，不替玩家自动改阵型。招募后进入战斗前同样提示，不能等到首个商店才发现站位限制。
- 确认后先统一普攻/技能候选目标查询，再接示例、提示与范围修改来源。保留无范围配置旧内容的兼容默认值，再逐步迁移，避免一次使现有英雄全部失效。
- 验收应覆盖：双方镜像、范围与优先级分离、无目标零资源消耗且其它行动继续、单人/未满队、前排死亡与补怪、清场余单怪、施法中目标死亡/重选、旧弹道不得打新怪、装备增删冲突恢复、预览不改变随机流、高频下表现与逻辑一致。

待用户确认的主要取舍：是否采用“普攻优先使用存活顺序范围保证基础输出，技能使用固定位置与部分自身站位限制”。本轮仅记录方案，未运行游戏测试或部署新机制。
