# 快捷说明、战斗反馈与手机横屏方案

日期：2026-10-16（北京时间）。关联进度：R006、UI-02 / UI-03 / UI-04。

**状态：方案待用户确认，未实施。** 用户已要求开展这三项工作，同时明确“需要设计的先设计给我确认再开始”。本轮只提交方案与进度记录；以下尺寸、交互和表现预算均是建议，不能作为现有功能描述。

## 1. 技能和装备的快捷查看

### 打开与关闭

- 电脑：指针停留技能/装备图标约 400ms 后出现小型说明卡；扫过不打开。图标和说明卡共同构成停留区域，跨越间隙约 150ms 内不闪退。离开两者后关闭；点击图标可固定说明，点击空白、关闭按钮或 Escape 关闭固定卡。键盘聚焦可查看，Escape 关闭。
- 手机：轻点技能/装备图标打开说明，点空白或关闭按钮收起。轻点战场英雄只切换当前英雄面板，不打开说明、不暂停。
- 所有说明保持局部，不给整个战场加暗色遮罩。只保留一张说明，切换对象直接替换内容。
- 商店继续保留“点击商品选择、拖图标穿戴、点击已装备物品打开出售/转移小浮窗”；电脑悬停查看不选中、不交易，手机商品的名称/属性已直接可见，完整说明可用独立信息按钮展开。拖动开始关闭说明并取消悬停计时，拖后不误弹说明。

### 说明内容

技能显示名称、被动/主动、目标规则、效果、实际消耗、计入急速后的当前冷却，以及剩余冷却/施法限制。尚未实现的专属技能或效果继续标注为演示/占位，不把描述写成已经生效。

装备显示品级、属性、特殊效果和每人橙装限制；商店展示购买/出售价格。战斗中不出现可穿戴、出售或拖动交易入口。说明数据读取现有定义与当前单位，不能通过查询消耗随机数、法力或触发效果。

### 暂停与手动大招

- 战斗中说明真正显示时暂停逻辑、冷却、关卡倒计时、弹道、粒子和浮字；400ms 悬停等待期间继续运行。显示轻量提示“查看说明 · 战斗已暂停”。
- 关闭仅解除“说明暂停”。若原本手动暂停、切到后台或同时有其他暂停原因，不能擅自继续；恢复不追赶暂停期间的时间。切换说明对象保持暂停，不在中间偷跑一帧。
- 为避免手机“点 R 看说明”误施法，建议将说明与释放分开：R 图标点击查看；切到手动模式后另显“释放大招”按钮，电脑/手机一致，单击执行。按钮显示剩余冷却/法力不足等原因，无效时不消耗资源。
- 释放按钮是明确的行动操作：查看说明时按下，关闭说明并再次检查可释放条件后执行；只能解除说明暂停。仍存在手动/后台暂停时不可执行，需要先明确继续。保持现有目标规则，不增加手动选目标系统。
- 需要用户确认的行为变化：当前代码手动模式点击 R 直接释放；建议改为独立释放按钮，以统一查看体验。

## 2. 战斗信息与高频表现

| 事件 | 建议表现 | 文字示例 |
| --- | --- | --- |
| 普攻 | 浅色细弹道，较小数字 | `−36` |
| 伤害技能 | 更醒目的青色弹道，短暂技能标记；颜色表示来源类别，不表示物理/魔法伤害 | `Q −85` |
| 暴击 | 金色、略大，保留普攻/技能来源类别 | `暴击 −72` |
| 实际治疗 | 绿色加号 | `+24` |
| 获得护盾 | 蓝色盾标记和加号 | `盾 +40` |
| 护盾吸收 | 独立盾标记，区别实际生命损失 | `盾 −30`；穿盾部分另记生命损失 |
| 闪避 | 灰色短字，无伪伤害数字 | `闪避` |

来源单位发出攻击时短暂提示，受击单位在到达结算时反馈。选中英雄后优先突出其弹道与本次目标，目标提示只对应具体事件，不固定高亮已经换位/死亡/刷新的目标。不持续绘制十名角色的常驻连线。

### 浮字预算（建议初值，可根据验收调整）

- 同一单位最多同时显示两组浮字；桌面总量最多 24 组，手机最多 12 组。
- 约 300ms 窗口内同一来源、同一目标实例、同一技能/普攻类别、同一结果类别的重复结算合并为 `−120 ×4` 等累计提示；暴击与非暴击、治疗与伤害、获得护盾与吸收不得混算。
- 累计的是实际结算数值，合计后再格式化，不能用四舍五入后的单次数字相加；目标 ID 更换立即分组，不能合并进新刷出的怪。
- 超过视觉预算优先保留选中英雄、重要暴击和死亡等反馈；压缩或略过低优先级表现，不延迟/丢弃真实伤害与触发，不消耗模拟随机数。死亡不要求必占一条伤害浮字，可用角色表现呈现。
- 暂停冻结合并窗口与显示时钟。先前已结算的浮字不得因查看说明重放或重复累计。

### 现有代码需要补齐的信息

当前 EffectEvent 记录目标、结果类型、数量与暴击；伤害结果尚不能完整区分普攻、具体技能及触发来源，且展示层用 `实际扣血 || 护盾吸收`。实施时需补充只读的来源单位 ID、来源类别/技能标识，以及生命损失/护盾吸收分量。不能仅靠数字颜色推测来源，也不改变战斗结算顺序。

## 3. 手机战斗横屏布局

电脑继续显示五名英雄的完整底栏；手机横屏采用“十单位全景 + 当前英雄详情”，避免把五块完整属性面板一并缩小。

| 区域 | 建议内容 |
| --- | --- |
| 顶栏 | 层数、时间、金币、暂停；装饰文案收起 |
| 中央战场 | 左五英雄、右五敌人同屏，不需要横向滚动；保留前后排方向和编号 |
| 英雄切换条 | 五个可点击名字/头像，标记当前选中英雄；能看出其他英雄大招是否就绪 |
| 底部详情 | 只展开当前英雄：被动 + Q/W/E/R、四装备槽、自动/手动开关与独立释放按钮；属性通过切换查看主要/次要两页 |

- 在约 844×390 的横屏上，建议顶栏 32–36px、战场约 170–190px、英雄切换约 40–44px，其余给紧凑详情；按实际可用高度和安全区调整，不硬锁为固定像素总和。
- 下方“技能/装备”和“属性”切换是同一英雄详情内的视图，不增加整页导航，不阻塞战斗；主要/次要属性继续沿用既有分组。
- 场上一直保留每个单位的血蓝条、当前/上限和攻击进度。大数可缩写；**手机上每秒回复值和精确大数移入选中单位详情**，电脑仍保留当前显示。这一信息取舍需用户确认。
- 技能、装备、英雄切换及释放按钮触控区域尽量不小于 44×44 CSS px；战场角色可点击范围与视觉卡片分开，避免十卡并排时只能点中文字。
- 手机竖屏提供“横屏查看完整战场”提示与精简状态/暂停入口；浏览器不强制锁屏。战斗中从横屏旋转到竖屏自动暂停，回到横屏后让玩家点击继续，避免布局变化时误操作。不把“完整竖屏战场”纳入本次范围。
- 说明卡在屏幕可用区域内定位、可滚动，不遮住关闭按钮；尺寸/旋转改变时重新定位或关闭并保留正确暂停原因。
- 不增加战斗中换位或穿脱装备，不改变商店拖动规则。
