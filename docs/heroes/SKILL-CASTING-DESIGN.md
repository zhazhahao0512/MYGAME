# 技能释放 V0.4 · 托管释放、自动释放、点击释放

2026-10-19（北京时间），R041。[D019](../decisions/D019-three-casting-modes.md)确认三模式及蓝量/技能等级参与托管；[D020](../decisions/D020-skill-mode-circle.md)进一步确认默认全托管、逐技能独立设置及图标右上角小圆钮切换。统一名称为“托管释放／自动释放／点击释放”。R043已获实施授权并接入当前原型，见[D022](../decisions/D022-casting-implementation.md)和[当前运行契约](../COMBAT.md#r043--逐技能三模式当前实现)。下文区分原方案与实际接入范围，未改英雄/装备数值，不宣称实战平衡。

本版接续V0.3，取代旧R专用二态开关；默认全托管、逐技能圆钮、独立点击释放、1–4标签及保存均已接入。岚牙、正式技能加点、新精准/装备仍未迁移。R037/V0.1旧方案保留在Git49b36b7，不作为现行主方案。

**首版实现范围（R043）**：按当前示例技能读取真实效果/消耗/冷却；可选rank/ranks支持有等级定义的数据，但本轮未接入完整技能升级界面。已实现单技能留蓝、救急/关键收割/打断、有效治疗/防护、普通自动和点击仲裁；使用原生20ms行动机会评估、8秒准备、同用途25%切换阈值和1.5秒点击短指令。当前没有岚牙攻击特效、大招维持1/2等运行机制，相关模板与预设连招仍是后续设计，不能冒充已完成。

## 1. 三种模式的承诺

| 模式 | 行为 | 不承担的决策 |
| --- | --- | --- |
| 自动释放 | 每次允许行动时，只要学会、冷却完成、有蓝且有合法目标就使用 | 不为其它技能留蓝，不等待更多敌人，不计算当前是否最划算 |
| 点击释放 | 玩家点独立释放按钮才执行；系统不自行使用 | 不因低血或首领出现而偷偷切回自动 |
| 托管释放 | 根据法力、当前技能等级、装备、增益状态及战况决定放什么、何时等一下 | 不保证等同全知最优，也不改变伤害/耗蓝/冷却 |

“好了就用”指下一个合法行动机会，不指取消正在吟唱的技能或同帧无视时序。三模式共用硬合法性；技能定义明确禁止重复施放的状态、4接管1/2、无合法目标等仍不可绕过。如果技能定义允许提前刷新，那么自动释放可浪费剩余增益/次数，托管才负责避免这种浪费。收益条件与真正的禁用条件必须分开实现。

每个主动技能独立选择模式，默认全部为托管释放；在各自图标右上角用小圆钮切换，允许1/2托管、3点击、4自动等混搭。用户所说“全托管优先”落实为默认设置和主要使用方式，不据此改变混搭中的资源仲裁顺序。普攻继续自动，被动没有释放模式，不再叠加三套用蓝预设。此前整英雄快捷设置只属建议，本轮不增设额外常驻全局开关。

## 2. 混合模式如何争抢同一份法力

同一个英雄共享行动与法力，建议仲裁顺序为：有效点击指令 → 自动释放候选 → 托管候选 → 普攻。每次成功启动技能后更新状态/法力，再重新检查；不能按旧快照重复花同一份蓝。

- 自动释放内部采用英雄固定的明确顺序；岚牙首版可沿用4→2→1→3作为机械基线，同优先级按技能编号。它不根据等级或战况偷偷改变顺序。
- 自动释放可以花掉托管准备留的蓝；托管无权暗中拦截。混搭因此可能破坏托管计划，显示“法力被自动释放技能消耗”，不把无法保证的结果说成保证大招准时释放。
- 点击指令也可以突破托管软储备，但须满足真实资源与行动条件。只有托管技能之间才采用救急、收益与留蓝排序。
- 点击释放的技能默认不参与托管储备；自动释放技能也不被托管保护。首版不再提供另一个常驻“为手动技能留蓝”开关，避免模式叠套。未来若确需临时“为这次手动施法准备”，应另设计明确的一次性指令。

全托管适合系统完整安排蓝量；混搭则尊重玩家主动指定的行为。不会承诺全托管始终优于自动释放或手动，需通过同条件数据验证。

## 3. 托管：先分紧急程度，再比较收益

系统只读取当前可见状态与已知技能规则，不看未来随机数、未公开刷怪或事后最优结果。R043按当前原生20ms行动机会重算，实际释放前再次验证；0.25秒缓存留待性能证据需要时评估。

| 层级 | 何时进入 | 判断重点 |
| --- | --- | --- |
| 1 救急 | 可用防御/治疗/控制能缓解当前实际威胁 | 受益目标、缺失生命、近期受伤和效果是否能及时到达；不是所有低血时的攻击技能都算救急 |
| 2 即时制胜 | 高可信度击杀危险敌人、打断正在吟唱的危险技能 | 当前目标、预计命中、非过量部分；靠一次低概率暴击才能击杀不算稳定收割 |
| 3 核心运转 | 开启或恢复英雄核心机制，且当前确有持续发挥空间 | 当前等级的技能效果、现有增益和配合关系；不固定为4，也不固定某个普通技能编号 |
| 4 补充收益 | 群伤、补命中、次要增益等 | 实际目标数、缺口与资源余量；本来已有充足覆盖则延后 |

技能的层级随状态变化。岚牙3平时补群伤，受压时可进入救急；主升3且面对多目标时也可能成为当前核心清场手段。分层是选择流程，不给每个技能永久贴高/低优先级标签。

同层先比较当前可兑现的边际收益，稀缺蓝量时再重点比较每点法力收益。首版不把伤害、治疗和控制硬加成一个全职业“总战力分”：先由英雄策略模板定义本层目标，再在同一目标/单位中比较；不同职责仍按上述层级及英雄模板取舍，避免虚构“1秒眩晕=固定100伤害”。

## 4. 技能等级怎样真正改变优先级

不能仅给“4级技能加40分、1级加10分”，也不强制满级普通技能高于1级大招。每次估算必须使用**当前实际技能等级**：伤害/治疗/盾量、目标上限、持续时间、冷却、蓝耗和特殊机制都读取当前值。

采用统一短观察窗口，首版建议H=8秒；长增益额外显示完整持续期的价值作为复核，不能把短窗口评价当作最终平衡。计划比较如下：

- 伤害技能：当前目标与抗性/护盾下的预计有效伤害，扣除明显过量与施法占用损失。命中使用期望，不提前抽真实命中随机数。
- 攻速等增益：在H内比“不放这个技能”多出的预计攻击/附伤，不把原本就能打出的普攻全算成技能贡献。目标不足、将死或自身受控会缩短兑现时间。
- 治疗/护盾：预计实际能回复/吸收的部分；满血过量治疗、现有护盾覆盖、护盾持续时间内没有压力都压低收益。
- 精准/闪避：只算实际命中率变化与该时段攻击/承伤；已达100%命中时，不再给精准虚假加分。
- 组合：同一轮如1→2、2→1、4接管1/2，先算整段行动的差值，再分配消耗；不把同一份附伤或攻速收益重复计入两技能。只允许有限的英雄预设组合，不全量搜索未来战斗。

有蓝时优先同层内当前有效总收益；蓝不足以支付本轮值得放的候选时，比较`预计有效收益/实际耗蓝`，并考虑当前目标与施法时间。零耗蓝技能单独比较收益/行动占用，不除以0；效果近似时用较短行动占用、已等待时间、英雄预设顺序稳定打破平局。技能等级已通过实际效果进入估算，不再额外重复加一份等级奖励。

因此，1升满、2只1级时，1有机会成为更优的法力用途；2升满且装备附伤很多时，2可能优先；3升满且能打三人时，3可能优先。它们是机制推断示例，**并非本轮新跑出的最优顺序**；不能把“主升技能”写成无条件先放。

## 5. 蓝量规划：先想放什么，再看能否付费

维护两个候选集合：

1. **现在可释放**：所有硬条件满足，包括真实法力足够。
2. **值得准备**：已学习的托管技能/预设短组合，当前战况值得用、冷却将在准备窗口内结束，但法力可以暂时不足。

关键是第二组不能提前按“没蓝”删除。否则昂贵技能永远进不了计划，低费技能会不断抢走法力，重现R033的问题。首版同时只保护一个目标技能或一个预设短组合；组合的支付时点分别计算，不为四个技能各冻一份蓝。

计划选择依第3/4节的层级和当前等级收益。选定后保持到释放、目标/收益失效、模式变化或出现更高层需求，不每0.25秒因为微小分差来回切换；同层只在有明确收益变化时重选，R043同层同用途提升超过25%时重选，仍可按模型校准。

准备窗口建议8秒，单技能的自动软储备为：`B=max(0,实际耗蓝C−保证回蓝g×剩余冷却T)`。只有T≤8秒且计划有实际收益才启用；普通托管技能支付后需剩余至少B。准备开始时蓝已不足可能延后释放，不能承诺准时。

- g只计能覆盖该窗口的保证回复；不预支随机命中回蓝/击杀奖励。急速、蓝耗变化、回蓝装按实际更新。
- 保留对象本身可使用这份蓝；更高层救急/即时制胜可打破储备，不能为了未来输出现在坐等死亡。
- 无目标、仅剩明显可普攻收掉的敌人、当前最大蓝不足以支付、零回蓝且当前也不足以支付时取消无效储备。等真实资源变化后再评估。
- 若所有技能都不值得放或应等回蓝，正常普攻，不把“托管”等同停止行动。
- 不按固定“低于30%蓝就停技”处理：满蓝池不同，关键技能花费也不同。先看当前蓝和保证回蓝能覆盖哪些有效行动；蓝充裕可放补充技能，蓝紧张优先当前目标的高效率行动与保留计划。
- 40秒仅停止补怪，不代表战斗结束。已明确进入无后续补怪的清场且当前敌人预计两次普攻即可收掉时，才解除未来爆发储备；不能在40秒一律把蓝花光。

岚牙例：已选择100蓝的大招作计划，剩余4秒冷却，保证回蓝4.94/秒，B=80.24。当前110蓝时，托管1不能再花34（剩76）；当前120蓝时可以（剩86）。若1是“自动释放”，则110蓝也会立即支付34，托管只能重算计划；若1为“点击释放”，玩家不点就不花蓝。相同蓝量下三模式行为因此可解释且有区别。

## 6. 岚牙托管模板示例

| 状态 | 托管倾向 | 必须保留的边界 |
| --- | --- | --- |
| 稳定单目标 | 按当前等级比较1的附伤与2带来的额外攻击/特效，缺哪个有效增益就评估补哪个 | 不永久写死2先于1，不重复覆盖尚能利用的次数/增益 |
| 有两到三个目标 | 提高3的清场价值，和当前1/2收益比较 | 最多三个不同目标，不把五敌当五箭，不因群伤无视蓝耗 |
| 正在受伤且生命低 | 3的闪避可进入救急；首版可用≤35%生命且最近2秒受伤作触发候选 | 要确实有受益，不让4作为纯输出技能自动冒充治疗 |
| 4值得开启 | 按4当前等级真伤倍率及已学1/2效果估算整体价值，纳入留蓝 | 未学1/2不白送等级；已学低级4不因此失去组合价值 |
| 4正在生效 | 1/2由4维持；3看多目标、精准缺口或防御需求 | 1/2三个模式均不能重复施放，这是技能机制边界 |
| 仅剩低血单目标 | 倾向普攻或便宜有效技能，降低长增益/大招优先级 | 不读取未来随机数，不假设未公开怪物会马上出现 |

该模板继承核心/配合/有限补短板方向，允许等级和装备改变相对价值。技能状态判断必须区分硬规则和托管建议：例如1/2被4接管是硬规则；等待更多目标再放3只是托管策略，“自动释放”不受后者阻拦。

## 7. 操作、暂停与解释

每个主动技能图标右上角放一个独立小圆形模式按钮，点击按 **托管释放 → 自动释放 → 点击释放 → 托管释放** 循环。默认停在托管释放，设置属于具体英雄的具体技能；切换一个不影响其余技能或其他英雄。此位置、独立粒度、默认值与三名称已由用户确认；循环顺序和以下交互细节按该要求设计。

- 圆内建议分别显示“托／自／点”，辅以不同颜色；不只靠颜色辨认。悬停或键盘聚焦显示完整名称和“点击切换至……”提示，无障碍名称包含英雄/技能及当前、下一模式。
- 小圆钮仅切模式；其点击不冒泡到技能图标，不触发查看说明、手动施法或选敌。只响应一次完整点击，避免触屏事件重复切两档；键盘Enter/Space同样一次切一档。
- 视觉保持小圆，R043手机独立28px点击区/23px圆面，避免覆盖说明或邻近圆钮；其它主要按钮保留44px。尺寸经横屏布局检查，仍需真机反馈，不以无限扩大透明覆盖区解决。
- 图标主体继续查看技能说明；点击释放模式使用独立“释放”按钮。圆钮与释放按钮职责分开，不因“点击释放”名称把图标说明入口改成施法。电脑400ms说明悬停及手机轻点说明保留；圆钮提示本身不触发说明暂停。
- 冷却、缺蓝、未学会或受控不妨碍预先设置模式，但不能绕过真实施法限制；被动不显示模式圆钮。切换不重置冷却、消耗法力、取消已经开始的技能或清除现有增益。
- 模式变化后刷新显示和托管计划，离开托管释放的技能不再占用其预留法力；按既有候选规则清理该英雄尚未开始的临时点击指令。切入自动/托管后只在下一合法调度机会评估，设置动作本身不调用施法。
- 暂停时允许修改模式，但不解除任何暂停原因、不推进战斗。建议按英雄实例与技能保存本局选择，切换查看对象、跨关和读档保持；新英雄/新远征及缺少该字段的旧存档默认托管。R043已实现上述保存迁移，旧大招auto字段退出控制，缺少新字段按全托管恢复。

建议快捷键1–4仅对选中英雄发一次释放指令，焦点在输入/模态时禁用、长按不重复；实施前核对现有键位冲突。

自动释放或托管下也可点击立即下令，执行后仍保留所选模式。点击待执行机制沿R037候选：每英雄一条、最多等待1.5秒模拟时间，只等待自身正在执行的动作；缺蓝/冷却/受硬控不排长期订单。已经开始的动作不取消，已发普攻弹道/普攻冷却不额外算作技能占用。新有效指令替换旧指令，执行前再校验，失败说明原因。

等待点击指令期间不启动该英雄新的自动消费；换查看对象不改指令所属英雄，目标在实际开始施法时按技能/选敌规则确定。已启动吟唱与弹道仍绑定原契约。死亡、战斗结束、退出或该英雄模式切换清理临时指令；暂停冻结等待，跨关只保存模式不保存指令。

查看说明时释放可关闭说明并仅解除说明暂停；仍有手动/后台/旋转暂停则不执行、不新增队列，保留R007规范。不会新增暂停时排队一整套连招的系统。

托管显示“为4留蓝／先维持1／等待更多目标／当前收益低”，点击模式显示“等待点击”，自动释放显示真实冷却/缺蓝/目标限制。只显示当前主要理由，不每帧刷消息；详细推导留在调试报告，不要求玩家阅读公式。

## 8. 验证与后续
